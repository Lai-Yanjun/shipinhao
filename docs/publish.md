# 发布

生产和发布是两件事。这份文档只管成品包出来之后的部分：发到哪个号、怎么发、
什么时候值得自动化。

## 一、账号：用独立栏目号，不要用现有的个人号

不是因为不想让熟人看见才新开号，是这个项目本身要求新号：

1. **推荐标签是养出来的。** 平台靠历史内容给账号打标签决定推给谁。在已有内容
   方向的号上混发本栏目，两边标签互相稀释，新内容拿不到精准流量，旧内容的池子
   也被污染。
2. **打法是一周扔 20 条试选题。** 这个频率发在熟人可见的账号上社交成本很高，
   人会因为顾忌而不敢试 —— 而试错成本近乎为零正是这门生意成立的前提
   （见 README「为什么是这个技术路线」）。账号选错等于把这个前提毁掉。
3. **栏目号能独立于人存在。** 可以复制矩阵、可以交给别人运营、可以拿去谈合作。
   绑在个人号上这些都做不了。

### 开号门槛

| 平台 | 门槛 | 说明 |
|---|---|---|
| 小红书 | 低 | 新手机号即可，App 内多账号切换，日常运营不痛苦 |
| B 站 | 中 | 新手机号 + 投稿需实名。一个身份证能认证的账号数有上限，以平台当前规则为准 |
| 视频号 | 高 | 视频号绑死微信号，一个微信号只有一个视频号，要新视频号就要新微信号 |

硬门槛只有手机号一个。用运营商副卡或互联网套餐卡；**不要用接码平台的号**
（号码会被回收，账号等于随时可能丢），虚拟运营商号段（170/171 等）部分平台
直接拒绝注册，微信尤其严。实名用自己的身份证没问题，平台普遍允许一人多号。

视频号是最麻烦的：注册新微信号需要老用户辅助验证，且一个身份证能绑定微信支付的
微信号数量有限；同时视频号分发对社交关系链的依赖明显高于另两个平台，零好友的
新号冷启动很难。有营业执照的话，用**企业主体**注册视频号是最干净的解法。

### 开号顺序

先开**小红书 + B 站** —— 这两个新号冷启动纯靠推荐分发，跟有没有粉丝无关。
跑 20~30 条把选题和文案验证出来之后，再解决视频号的账号问题。那时候手里已经有
一批验证过的成品，不会浪费在冷启动期。

### 不要做的事

- 不要用这些号互赞互关。同设备的互动行为是判定「刷量矩阵」最直接的特征。
- 不要用模拟器、群控、养号工具。
- 不要买现成账号：有找回风险，历史违规记录会继承。
- 发布的 IP 与设备环境要稳定，别今天手机明天网页端后天换个网络。

## 二、发布方式：分两个阶段

### 阶段一（当前）：手动上传

成品包出来之后，人工传到三个平台，然后回填台账：

```bash
python cli.py publish --slug <slug> --platform 视频号 --url <链接>
```

`publish` 只写台账，不做任何上传。

**现在不接自动化，理由是：**

1. **新号 + 自动化上传 = 风控最敏感的组合。** 新注册账号本来就在观察期，第一批
   内容就用无头浏览器传上去，是拿账号做实验。
2. **省不下多少时间。** `verify` 是人工闸门，每期都得人过事实核查与合规自检。
   人已经在电脑前了，手传三个平台每期多花 5 分钟；换来的是不用维护 cookie 失效、
   不用跟平台改版、不用折腾 Chromium 兼容性 —— 这三样是持续成本，不是一次性的。
3. `docs/compliance.md` 第五节判断的另一半仍然成立。本地跑消掉了云端 IP 异常的
   风险，但「自动化上传的行为特征与正常创作者差异明显」这一条没变。
4. **量级还不需要。** 值得接自动化的时间点是开始铺矩阵号：几十个号 × 每天的量，
   手动才真的扛不住。

### 阶段二：接 social-auto-upload

选定 **[dreammis/social-auto-upload](https://github.com/dreammis/social-auto-upload)**。
浏览器自动化（patchright，反检测导向），覆盖抖音、视频号、小红书、B 站、快手、
微博、百家号、TikTok、YouTube 等 11 个平台。

与本项目三种成品形态的匹配：

| 成品 | 覆盖情况 |
|---|---|
| `video_9x16.mp4` → 视频号 | 支持（`tencent_uploader`，视频；图文不支持，无影响） |
| `xiaohongshu/` 图文轮播 | 支持图文上传 |
| B 站 | 支持，其 B 站部分包的是 [biliup](https://github.com/biliup/biliup)（走投稿接口，不靠浏览器） |
| `wechat_longpic.jpg` → 公众号 | **不覆盖**（它有的是百家号，不是公众号） |

公众号只能走微信官方 API（草稿箱 + 发布接口），个人主体订阅号的接口权限受限，
拿到号之后再确认能不能用。在那之前公众号长图手动发。

**备选**（按平台拆开接，比一个大而全的工具更可控）：

- B 站：[biliup/biliup](https://github.com/biliup/biliup)，走接口不走浏览器，最稳
- 小红书：[xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)，
  MCP server，支持图文发布，能直接被 Claude 会话调用，和本项目 Agent 主导的架构契合

### 切换条件

阶段一跑够 30~50 条、账号有基础权重、流程稳定之后再接阶段二。不要在冷启动期接。

真接的时候，在 `cli.py publish` 旁边做一层发布助手抽象：先实现 `manual`
（打开成品目录、按平台把文案送进剪贴板、打开平台上传页、发完提示贴回链接自动回填），
之后把实现换成 social-auto-upload 即可，上层不用改。
