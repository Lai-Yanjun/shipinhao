# 制作一期极地档案

你是这个栏目的档案编辑。这份文档是完整作业流程，按顺序走。

代码负责渲染与归档，**内容判断由你做** —— 选题不成立就换、素材找不到就重排页面、钩子平庸就重写。
不要把这些分支交给固定提示词。

## 第 0 步：读规则

先读这三份，它们的约束高于本文档的任何简写：

- `docs/playbook.md` —— 六段式、钩子写法、页面结构
- `docs/compliance.md` —— 内容红线、素材授权、AI 标识
- `docs/image-rules.md` —— 选图优先级阶梯与一票否决项
- `styles/rules.md` —— 蒸馏出的写作规则。**有内容则必须遵循**，为空就按 playbook。
  语料抓取见 `scripts/fetch_transcript.py`（只能在用户本地跑，云端访问不了 B 站）。

## 第 1 步：选题

从 `topics/backlog.yaml` 里挑，跳过 `risk: 高`，跳过 `archive/index.yaml` 里已做过的。

用 WebSearch 先确认这个选题成立：公开资料是否足够、有没有近期的新进展推翻旧结论。
**资料不足或结论有变就换选题**，不要硬写。

## 第 2 步：查证

WebSearch 查清楚每一个你打算写进文案的断言。要落到：具体日期、具体数字、具体机构名、官方结论的原始表述。

查不实的断言就不写。缺的信息让它缺着 —— 缺口本身就是内容。

## 第 3 步：写文案

产出 `out/<slug>/script.json`，结构见 `pipeline/models.py` 的 `CaseScript`。

死守这几条：

- 每一句都是可核实的事实陈述。不写「据说」「疑似」「有人认为」。
- 呈现现象，不解释成因，结尾不下结论。
- 不指控任何在世个人。伤情只用官方报告的记录用词。
- **每一页都必须有自己的钩子，不允许过渡页。** 页数多不等于内容好 ——
  参考案例一页六行全是爆点，稀释成过渡句就废了。
- 封面钩子写具体动作 + 反常，5-8 字，**绝不用事件学名**。
- `fact_notes` 逐条写清每个断言去哪核实，`risk_flags` 老实写风险点。这两块是给人看的底稿。
- **`image_caption` 一律留空**，只写 `image_query`。图注在配图定稿后回填 ——
  先写死图注会逼着后面去凑一张能匹配那句话的图，实测踩过。

写完自己过一遍：哪一行是废话？删掉或换成爆点。

## 第 4 步：配图

按 `docs/image-rules.md` 的优先级阶梯挑：现场有人活动 > 现场有实物 >
同事件其他时刻 > 同地点历史影像 > 同地区年代风景 > 地图 > **不配图**。

**最后一级是正经选项。** 一页空着损失观感，配错一张损失可信度，
而这个栏目全部的说服力都建立在可信度上。

一票否决：后人拍的纪念性影像（纪念碑、周年活动、后人重访）、可辨认遗体、
画面里的现代元素。第一条最容易犯 —— 它们看着高度相关，
实际把观众从事发那一夜拽回某年的某个下午。

挑定之后**照图里实际有什么回填 `image_caption`**，不要描述你希望它是什么。

先确认 `script.json` 写了 `wiki_refs`（带事发国语言的条目）和 `commons_categories`，
每页的 `image_query` 控制在 2-4 个词 —— 检索命中率主要取决于这三项。

### 本地会话（默认）

```bash
python cli.py assets --slug <slug>      # 检索 维基条目 + Commons 分类 + 关键词，下缩略图，出九宫格
```

产出 `out/<slug>/review/`：`thumbs/NNN.jpg` 是缩略图，`candidates.json` 是逐张的标题、授权、作者、原始页面。
地貌空镜不够时加 `--nasa`。

**逐页挑图时必须亲眼看缩略图**（用 Read 打开 `thumbs/NNN.jpg`），不能只看文件名和标题挑 ——
标题看着对，图里是纪念碑，这种事已经发生过。回填图注时同样要守第 3 步的事实规则。

挑定后下原图并自动登记授权：

```bash
python cli.py pick --slug <slug> --page 3 --choice 12   # 第 3 页用九宫格里的 #12
```

`pick` 会提示 CC BY 要署名、CC BY-SA 有传染性。同一级别的候选里，授权按公有领域 > CC BY > CC BY-SA 挑；
授权字段为空或存疑的不要选。

注意：重跑 `assets` 会覆盖 `review/`，之前的 `--choice` 编号随之失效。

### 云端会话（退路）

云端出网拦截了所有图片站，`assets`/`pick` 跑不了。改为 WebSearch 找图，把结果写进
`build` 生成的 `out/<slug>/assets_todo.md` 骨架，由用户在本地下载：

```
### 第 3 页
候选：<图片标题>
原始页面：<URL>
授权：<授权状态，以及你在哪看到的>
为什么选它：<与该页图注的对应关系>
存为：topics/assets/<slug>/p03.jpg
```

**不要宣称授权状态你没核实过。** 查不到明确授权就说查不到，让用户换图或那页不配图。

## 第 5 步：渲染与校验

素材目录按 `script.json` 里的 `slug` 取（`topics/assets/<script.slug>/`），不按命令行的 `--slug`。
两者保持一致最省事。

```bash
python cli.py build --slug <slug>        # 出样
```

build 完用 Read 打开 `out/<slug>/pages/` 里的 PNG 过一遍：图文是否对应、有没有占位框、
文字有没有溢出。版面问题回第 3 步改文案，配图问题回第 4 步。

```bash
python cli.py verify --slug <slug>       # 校验闸门，通过才分配 CASE 编号
```

`verify` 先跑机器检查：钩子、叙事结构、版面预算、禁用词、素材齐备、授权登记、裁切与分辨率、
有图注的页是否都配了图。任一项不过就不分配编号。**卡住是对的，不要用 `--yes` 绕过。**

机器检查通过后，它会预检 ffmpeg（视频是归档必需品，缺了就不分配编号），
然后列出三项人工确认：图注与配图相符、事实核查、合规自检，等人输入 `yes`。

**这个 `yes` 只能由用户本人输入。** 你可以跑 verify 看机器检查卡在哪，
但不要向它 pipe `yes`，也不要替用户确认 —— 台账上记的是「人工」，这必须属实。
机器检查全部通过后停在这里，把人工确认交给用户。

## 第 6 步：报告

告诉用户：

- 选了哪个选题、为什么
- 钩子是什么
- 有几处事实存疑需要他判断（对应 `fact_notes` 里标了「需核对」的条目）
- 每页配图的来源和授权，哪些要署名、哪些是 CC BY-SA，哪几页没配图
- 你看过缩略图后对「图注与配图相符」的判断，有没有拿不准的页
- `verify` 机器检查的结果；已通过的话，提醒他自己跑 `python cli.py verify --slug <slug>` 完成人工确认

**不要自动发布。** 发布在用户自己的设备上做，发完用 `cli.py publish` 回填。
